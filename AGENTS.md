# Working rules for agents on meshsonar (read first)

Flutter app (iOS/Android/desktop), version in `pubspec.yaml` (0.40.0+70 in the tree; release 0.41.0+71, build 71, is prepared and not cut yet: the integrator bumps `pubspec.yaml` and `test/app/app_version_test.dart` at release; the CHANGELOG entry for 0.41.0 is written). Platform state and open items: `meshsonar-infra/docs/HANDOFF.md`. Docs index: README.md "Documentation".

- **Privacy is non-negotiable.** On-air ping text is exactly `MS:` + 10 random chars (`lib/radio/wardrive_engine.dart`: `newPingTag`, `formatPingText`). Never put position, power, name or any identifier in it. Legacy `@[MapperBot]` fixtures in tests are captured packets; keep them.
- Layers: `lib/core` and `lib/radio` are pure Dart (no Flutter imports); UI in `lib/ui`; platform seams in `lib/platform`. Save-first: a ping is on disk before anything else happens (docs/ARCHITECTURE.md).
- Hex cells: coverage v2 (server capability `coverageV2`) uses ONE cell size, H3 res 11, at every zoom, coloured by the MEAN SNR band (`lib/core/coverage_v2.dart` `coverageBandOf`, same rule as SQL `ms_coverage_band`); colours in `lib/ui/map/coverage_bands.dart` copied exactly from meshsonar-infra `docs/planning/coverage-v2-colours.md`. The old path (no `coverageV2`) keeps the zoom table (`coverageResForZoom`, 7..11) = `cellToParent(geoToCell(res 11), res)`, never a direct lookup at the display res (about 6% differ). Ids are BigInt in Dart, lowercase hex strings on the wire. `test/hex_cells_test.dart` needs `brew install h3`.
- Release 0.38 (Master Planner + observer everywhere + MQTT feeds): the Plan tab is one Planner on one `PlanController` (`lib/core/plan/`, `lib/ui/plan/`), every node surface uses `NodeRef`/`nodeActions` (`lib/ui/nodes/`), the app is an observer whenever a radio is connected (no Home observer) and the MQTT engine lives in `lib/core/mqtt/` (public packets only, two privacy gates, radio-signed JWT; never add a field that carries position or a name). Planner endpoints are `/api/cmh/plan-*` (region = Host, no `region` body field); estimates are labelled Estimate in the UI; shared and exported positions of `mine`/`installed` nodes are rounded to about 1 km unless the sender turns Exact positions on. Universal links (build 66): `ios/Runner/Runner.entitlements` carries `applinks:meshsonar.com` and, from build 71, `applinks:*.meshsonar.com` for region-host Network links (Associated Domains is enabled on the App ID `com.meshsonar.app`); `https://meshsonar.com/share/plan#code` opens the same plan-inbox handler as `meshsonar://plan#code`; the export-only `scripts/release_ios.sh` signing gate (TEAM_ID=5MT44ZS3D6) must pass before an upload. Docs: FEATURES (Plan tab, Observer and MQTT feeds), ARCHITECTURE 1.3 / 1.4, PROTOCOL 14.
- Wire contract with the website: `docs/MESHSONAR_DRIVE_FORMAT.md` in meshcore-insights; JSON keys are pinned by a golden test (`test/core/antenna_profile_test.dart`). Changing a field means updating the website validator too.
- Always run `flutter analyze` and `flutter test` (thousands of tests, the count grows each release; `offline_packs_screen_test` can be flaky in a full run, run it alone to confirm) before a PR; bump `pubspec.yaml` and `test/app/app_version_test.dart` together; add a `docs/CHANGELOG.md` entry; update PROTOCOL/ARCHITECTURE/FEATURES if behaviour changed.
- **Test gate (Andy, Nov 10 2026, for speed; replaces "full suite after every commit"):** while working, run `flutter analyze` and only the tests next to the change (`flutter test test/<area> ...`). Run the FULL `flutter test` exactly ONCE per TestFlight build, right before the upload; if something fails, fix it and rerun only the failing test files, not the whole suite. Simulator screenshots (`verify_sim.sh`, iPhone + dark) only when the change touches screens or the map; skip them for logic/backend-only changes. Never delete a test to go faster; delete only tests of features that were removed. Andy's on-device reports are the safety net.
